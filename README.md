# 물때 · 낚시 예약 앱

업체 → 소속 배 → 출항 일정 → 예약 구조의 iOS·Android 앱 첫 버전입니다. Expo SDK 58, React Native, TypeScript, Expo Router를 사용합니다. 앱 이름은 변경 가능한 가칭입니다.

## 실행

```powershell
npm install
npm run web
# 휴대폰 확인용 개발 서버
npm start
```

웹 미리보기는 터미널에 표시되는 주소로 접속합니다. 휴대폰에서는 호환되는 Expo Go로 개발 서버 QR을 스캔합니다. 로컬 네트워크가 연결되어 있어야 합니다.

## 구현된 흐름

- 날짜·지역·어종·업체명·배 이름으로 출항 검색
- 업체의 여러 배와 배별 날짜·출항·귀항·낚시 종류·가격·정원 관리
- 인원별 예약, 독선 예약, 전액 시연 결제 후 즉시 예약 확정
- 좌석 초과 방지, 일반 예약이 있는 일정의 독선 차단, 독선 시 전체 좌석 잠금
- 내 예약, 취소 요청, 예약 시점 규정 버전 보관
- 운영자 직접 업체 등록 및 판매 승인, 미승인 업체 노출 차단
- 배 등록, 출항 일정 등록, 같은 배의 겹치는 출항 시간 차단
- 기상 악화·자연재해 취소 시 해당 출항의 전체 예약을 전액 환불 상태로 변경
- 기기 저장 및 재접속 후 데이터 복원, 저장 실패 시 입력 유지
- 출항 24시간 이내 빈자리 출항의 단골 우선 안내 대상·순서·시연 이력 관리

## 단골 빈자리 안내

운영 관리 → 단골 빈자리 알림에서 확인합니다. 출항 전 24시간 이내, 잔여석이 있고 판매 가능한 일정만 대상으로 합니다. 같은 배의 탑승 완료 회차가 많은 고객부터 안내하며, 동률은 최근 탑승 순으로 정렬합니다. 예약 건수나 동반 인원수를 탑승 횟수로 계산하지 않습니다. 미완료·미래 탑승은 제외하고 동일 출항의 중복 탑승 기록은 한 번만 셉니다.

빈자리 안내 수신 동의가 있는 고객 중 이미 해당 출항을 예약한 고객과 이미 안내를 받은 고객을 제외합니다. 실행 직전에 잔여석·출항 상태·판매 승인·동의를 다시 확인하며, 만석/독선/출항 취소/출항 시각이 되면 중단합니다. 안내가 좌석을 확보해주지는 않으며 결제 완료 순으로 예약을 확정합니다.

현재는 가상 단골 데이터를 명시적으로 불러온 후, 버튼을 누를 때마다 다음 1명에 대한 **시연 기록만 저장**합니다. 실제 푸시나 자동 스케줄러는 연결하지 않았습니다. 실제 서비스에서는 계정 ID에 연결된 검증된 승선 완료 이력, 고객의 수신 동의 설정, 푸시 토큰, 서버 작업 큐, 출항·고객별 중복 방지 키를 연결해야 합니다. 현재 시연의 기존 예약 제외는 테스트 전화번호로 비교하며 운영 환경에서는 검증된 계정 ID로 바꿉니다. 회차별 안내 인원·발송 간격·야간 처리·최근성 기준은 미정입니다. 같은 작업의 재시도 시 중복 발송되지 않도록 발송 작업 자체에도 멱등성 처리가 필요합니다.

추가 검증: 전체 테스트 15개 및 타입 검사·린트 통과. 브라우저에서 예시 고객 8회 → 5회 → 2회 순위와 첫 안내 후 다음 고객으로 진행되는 것을 확인했습니다. 화면은 `docs/vacancy-preview.png`에 저장했습니다.

인천제일바다낚시는 사용자가 제공한 예시 명칭입니다. 배 이름·가격·정원·어종·시간과 기타 업체는 전부 시연 데이터이며 실제 업체의 상품 정보가 아닙니다.

## 현재 범위

**서버·실제 결제·인증이 없는 로컬 시연 버전입니다. 실제 판매에 사용하면 안 됩니다.**

데이터는 브라우저 또는 휴대폰에만 저장되며 기기 간 공유되지 않습니다. 운영 관리 탭도 시연을 위해 열려 있습니다. 좌석 변경 작업을 한 저장 큐에서 순서대로 처리하므로 같은 앱 세션의 중복 좌석 예약을 막지만, 실제 서비스의 여러 사용자·기기 동시 예약을 보장하는 서버 트랜잭션은 아직 없습니다. 실제 개인정보 대신 테스트 정보를 입력하세요.

환불 정책은 초안 `draft-1`입니다. 기상 악화·자연재해 출항 취소는 전액 환불합니다. 이용자 사정 취소의 시점별 환불률은 미정이므로 취소 요청을 접수한 뒤 좌석을 유지합니다. 실제 결제 취소는 일어나지 않습니다.

## 검증

```powershell
npm run typecheck
npm run lint
npm test
npx expo export --platform web
npx expo export --platform ios --platform android --output-dir dist-native
```

도메인 테스트는 예약 금액, 잔여석, 독선 충돌, 판매 승인, 출항 시각, 입력 검증, 취소 요청, 전액 환불, 업체·배 등록, 출항 겹침을 다룹니다. 네이티브 번들 생성은 설치 파일 생성·기기 실행 검증과 다릅니다.

2026-10-20 검증: 타입 검사·린트·도메인 테스트 9개 통과, 웹·iOS·Android 번들 생성 성공. 브라우저에서 2인 160,000원 시연 예약 → 재접속 후 복원 → 취소 요청 → 기상 출항 취소 → 전액 환불 상태를 확인했습니다. 390px 너비에서 검색 결과 없음과 조건 초기화도 확인했습니다. 실제 iOS·Android 기기 실행은 아직 검증하지 않았습니다. 모바일 화면은 `docs/mobile-preview.png`에 저장했습니다.

설치 시 의존성 감사에서 경고 26개(중간 7, 높음 19)가 보고되었습니다. 자동 수정 제안은 Expo·React Native의 과거 주요 버전으로 변경하는 내용이므로 적용하지 않았습니다. 실제 배포 전 호환되는 업데이트와 전이 의존성을 다시 검토해야 합니다.

## 실제 서비스로 이어질 작업

1. 서버·PostgreSQL 연결 및 사용자/업체 직원/전체 운영자 권한 분리. 업체 등록·승인은 전체 운영자만 가능하게 제한.
2. 만료 시간이 있는 좌석 임시 확보와 DB 잠금. 가격은 서버 계산, 결제 검증 웹훅에서만 예약 확정. 중복 웹훅의 멱등성 처리.
3. PG 테스트 결제와 환불 연동. 기상 취소는 환불 대기 → PG 성공 확인 → 환불 완료로 처리하고 실패 재시도·감사 기록 보관.
4. 공통 이용자 취소 환불률 확정, 규정 본문과 버전 스냅샷 저장, 동의 이력 저장.
5. 승선 안내·예약 알림·업체 정산·고객 문의, 실제 사업자/항구/배 데이터 등록.
6. 실기기 접근성·키보드·네트워크 실패 테스트, 앱 아이콘·식별자 확정, 스토어 배포.

외부 바다 이미지는 Unsplash를 사용하며 이미지가 없어도 예약 기능과 텍스트는 사용할 수 있습니다.
